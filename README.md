# 话题棱镜 TopicPrism

给定一个话题，联网检索多平台信息 → 热度把关 → 事件去重 → 取前 N 条（默认 60）→ 先汇总后分类 → 输出报告。

## 目录

```
topic-prism/
├── SKILL.md                      主流程说明（人和 agent 都读这个）
├── README.md                     本文件：目录、设计要点、验证状态、局限
├── CHANGELOG.md                  完整变更记录（v1.2.0 起，按版本倒序）
├── LICENSE                       MIT
├── references/
│   ├── platforms.json            渠道分档与全部阈值（唯一配置源）
│   ├── taxonomy.md               七个分类维度（前六个必填）及打标红线
│   └── report-template.md        报告结构模板 + 质检清单
├── scripts/
│   ├── prism.py                  探水 / 打分 / 去重 / 取数 / 渲染 / 质检 / 播报文案
│   └── export_doc.py             导出 Word / PDF（含信源清单附录）
└── samples/
    ├── candidates.json           候选池字段示例
    └── out/                      跑通后的示例产物（selected.json + report.md）
```

## 收尾必做

报告交付后调用语音播报（`speak_text`），文案由 `prism.py notify` 生成，例如「调研完成。某话题，共 30 条：正文 11 条带热度依据、附录 19 条热度未知。报告已生成，拿起手机看结果。」——流程耗时长，用户往往已离开屏幕，这一步是用来把人叫回来的。

**能力来源**：`speak_text` 由本产物内置的「TTS」连接器提供（同一连接器还带 `stop_speak_text`，用户说「别播了」时用来停下正在念的那句）。设备不支持时按 SKILL.md 第九章的兜底链逐级降级：系统通知 → 对话里把结论置顶。要播报的是「通知用户」这个动作，不是某个具体能力——能力可以缺，通知不能省。

## 快速验证

```bash
cd topic-prism
python3 scripts/prism.py self-test          # 59 项断言，应全 PASS
python3 scripts/export_doc.py --selftest    # 50 项断言（未装 reportlab 时为 47 项）

# 完整管道：产出 out-demo/{scored,selected}.json + report.md
python3 scripts/prism.py run --in samples/candidates.json --n 6 --topic "示例" --outdir out-demo

# 质检与导出用已打标的示例产物（samples/out/selected.json）
python3 scripts/prism.py qa --in samples/out/selected.json
python3 scripts/export_doc.py --in samples/out/selected.json --format docx --out out-demo/demo.docx
```

**顺序说明**：`run` 产出的 `selected.json` 里每条事件的 `dimensions` 是空的，要由执行方按 `references/taxonomy.md` 填好，
再跑 `report` 渲染正式报告、跑 `qa` 做交付前质检。**刚 run 完直接 qa 会报一堆「缺分类维度」并以退出码 1 结束——这是设计如此，不是脚本坏了。**

`--outdir` / `--out` 只接受工作区内的相对路径，绝对路径与含 `..` 的路径会被拒绝。

## 使用前提

**脚本只做可机械化的事**——筛选、去重、排序、渲染、机械质检。
分类打标、来源质量评分、观点归纳、核查记录，全部由执行方模型在检索与读正文时产出。

因此：

- 宿主须具备联网检索能力，否则退化为「仅基于本地材料」并在报告注明
- 建议具备网页正文抓取能力；摘要、关键数据、核查依据都来自正文
- **报告质量取决于执行方模型的判断力**。`qa` 能拦「漏填 / 抄标题 / 套话」，拦不住「分类打错 / 来源评级虚高」
- 单次运行几分钟到十几分钟，话题越宽越久

## 设计要点

- **双层门槛**：绝对地板 100 + 平台分档（大平台 1000 / 中等 300 / 垂直 100），挡噪音不挡小众。
- **门槛判定（全池统计）**：用整个候选池的达标占比判定选题形态，达标占比 <50% 判为低热度选题，门槛下调至地板、不做分位截断，避免小众选题被砍到凑不够数；抽样会让占比随机漂移，因此不抽样。
- **事件去重**：URL 归一（去跟踪参数/子域）→ 标题 bigram Dice → 实体重合 → 同作者跨平台重发，用并查集做全局合并；跨平台分布转化为热度加分。
- **时间衰减**：`freshness` 占 10%，10 天半衰期，避免旧文靠陈年数据霸榜；`--days` 可收窄时间窗。
- **交付前质检**：`qa` 子命令查缺链接、归一后重复、缺分类维度、维度偏斜、探水样本不足。
- **模板化标题保护**：仅数字不同的系列标题（周报第 N 期）不误判为重复。
- **打分两段式**：本档内对数归一（门槛附近不归零，无断层）+ 同池分位再混合，跨档位分数可比，不再只是"各平台归一化近似"。
- **如实交付**：凑不满就报实际条数并说明，不拆条、不降地板、不重复计数。
- **输入校验**：路径错、JSON 非法、空池、缺 `title`、对象里没有候选数组，一律明确报错，不再被当成「话题没有讨论」的空结果；不合格条目逐条丢弃并提示。
- **热度未知不丢**：拿不到阅读/播放量的条目（公众号、小红书等）按固定配额进附录，正文满额也照常出现，不占 N 条名额。
- **来源质量参与排序**：五项加权里来源质量占第二权重（0.24），按站点 / 账号 / 页面三级证据打分。命中标题党、AI 批量水文、营销号的条目直接不进正文——这类内容靠的就是热度，扣分压不住。
- **关键数据聚合**：各条的 `facts` 去重后按更新时间倒序聚成一张表，数字不用自己从摘要里找。
- **观点分布与核查情况**：前者按立场分组给论点和论据，后者列出谁核查了什么、结论与依据；两者都不是标签堆砌。

## 文档导出与分发

- `scripts/export_doc.py`：导出 docx（标准库手写 OOXML，零依赖）/ pdf（可选 reportlab），含封面、目录、页码，文档含**附录 A 信源清单（全部链接）**、附录 B 热度未知条目、附录 C 落选条目与原因
- **交付渠道可选**：生成后先问用户选 飞书 / 企业微信 / 两个都要 / 只看不发，不选不发
  - 飞书：`lark-cli` 机器人身份直发（实测可用）
  - 企业微信：`wecom-cli` 上传拿 media_id 后发 file 消息（需先授权）
  - 个人微信：不支持文件，只能发文本
- 导出前同样做链接过滤与转义，DOCX 内链可点击

## 安全说明

- 脚本零联网：无 HTTP 客户端、无 `subprocess`/`eval`/`exec`、无凭证读取，只在指定输出目录写入 JSON 与 Markdown
- **输出路径边界**：`--outdir` / `--out` 只接受工作区内的相对路径，绝对路径与含 `..` 的路径一律拒绝并退出（自测有断言固化）
- 联网检索由调用方 agent 发起，**默认先告知并取得用户同意**才检索
- 输出消毒：外部标题/作者/摘要渲染时转义，非 `http(s)` 链接隐去，防 Markdown 注入
- 不采集、不存储任何账号与密钥；不代理访问第三方页面
- 许可证：MIT（见 LICENSE）

## 安装

作为插件安装：把整个 `topic-prism-plugin/` 目录交给平台，`plugin.json` 里已登记「TTS」连接器，`speak_text` / `stop_speak_text` 会一起带上。

**不要只拷贝 `topic-prism/` 这一个目录**——语音播报依赖产物内的「TTS」连接器，单独拷技能目录会丢掉它，第九章的播报步骤就只能走兜底链。

```bash
cp -r topic-prism-plugin <技能目录>/        # 整份插件，含清单与连接器登记
```

依赖：Python 3.8+ 标准库，无第三方包。

## 局限与不适用

### 什么时候别用它

| 场景 | 为什么不行 | 该走什么 |
|---|---|---|
| 单一事实查询（「某公司 CEO 是谁」） | 一次搜索就能答，走这个流程是浪费预算 | 直接查 |
| 要买卖建议、医疗诊断、法律结论 | 只做信息汇总与信源标注，不给结论性建议 | 找专业人士 |
| 要秒级突发、实时行情 | 检索有延迟，不是推送系统 | 行情/快讯类应用 |
| 只要某个指定账号或单一平台的全部内容 | 技能是多渠道抽样，不做单账号全量抓取 | 平台自带搜索 |
| 需要登录态、付费墙后的正文 | 红线明确不做，也不绕反爬 | 手动获取 |
| 要判断一条消息的真假 | 只能标注「已证实/待证实/存疑」，不能替代事实核查 | 官方通报、专业核查 |
| 要「全网热度排行」的绝对值 | 得到的是本次候选池内的相对热度分，不是全网排名 | 平台热榜 |
| 非英语语种的选题（日 / 韩 / 法 / 德等） | 只覆盖中文与英文源；英文源以技术、学术、国际事件为主 | 当地语言检索源 |

### 已知限制

- 各平台指标口径不同（阅读量/播放量/热度值/榜单名次），跨平台热度分只是归一化近似，**不是全网浏览量排名**。
- **热度分只在同一份报告内可比**：它包含「同池分位」，换个候选池分数就会变。两份不同报告之间不要比大小。
- 小红书的多数内容、部分公众号、部分垂直站点不公开量化指标，这类条目靠替代判据或进「热度未知」附录，覆盖度天然弱于微博/知乎。
- 私域内容（微信群、朋友圈、付费社群）与需要登录的正文一律抓不到，别指望覆盖。
- 分类是语义判断，由调用方按 `taxonomy.md` 打标，脚本只做规则校验与渲染——**打标质量取决于执行方的判断**，`qa` 只能拦住机械错误。
- 去重阈值对很短的标题（8 字以内）偏严，可能漏合并；同类系列标题（周报第 N 期）则刻意不合并。
- 60 条是目标不是保证：检索预算（默认 60 次）与真实可用信息量共同决定最终条数，凑不满会如实报缺口。
- 单次运行通常几分钟到十几分钟，取决于预算与话题宽度；结果不缓存，同话题重复调研会重新检索。

### 环境与依赖

- Python 3.8+，仅标准库（已用 3.8 语法校验）；PDF 导出才需要可选的 `reportlab`
- 联网检索由调用方 agent 发起，技能脚本本身零联网、不读凭证、**不写工作区之外的路径**（绝对路径与 `..` 会被脚本拒绝）
- 语音播报 `speak_text` / `stop_speak_text` 由本产物内置的「TTS」连接器提供；设备不支持时走兜底链，不影响结论交付
- 飞书 / 企业微信分发只在用户明确选择对应渠道时才需要 `lark-cli` / `wecom-cli`，默认只看不发
